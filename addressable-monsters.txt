# Monsters addressable by decision-characters
# NetHack 5.0.0, Unix terminal build (macOS and Linux), upstream base
# 16ff59115315917b93185d026aeefea06db9b0f4 plus this fork's decision hook.
#
# Which monsters can I enable?
#   enabled      Already uses the API on eligible turns (281).
#   candidate    Ordinary hostile turns fit the current providers (0).
#                Add a prompt row and a species encounter before shipping.
#   conditional  A plausible extension with a specific prerequisite (89).
#                Preserve the listed native behavior, add a provider or gate
#                where needed, and test the special encounter before enabling.
#   native-only  No independent ordinary decision turn in this build (13).
#
# All 271 candidates from the initial audit are now enabled alongside the
# original ten. Conditional rows are the development backlog. Each compiled
# PM_* appears once.
# Form IDs distinguish human and animal lycanthropes with the same name.
# Display names use NetHack's gender-neutral spelling. Player-role entries
# designate NPC adventurers. NUMMONS and NON_PM are sentinels.
#
# Runtime scope
#   The engine chooses among legal actions on one nearby hostile activation.
#   Tame and peaceful actors, special role flags (isshk, isgd, ispriest,
#   isminion), segmented worms, eating/helpless actors, an attached hero,
#   Conflict, and repeated player commands have native turn paths. Eligibility
#   follows the current form. Natural shapechangers also need an enabled base
#   form. The actual quest leader and Wizard retain native turn handling.
#   Waiting, sleep, detection and line of sight can
#   preempt a request. A species' speed, attacks, anatomy and terrain shape
#   its options. Passive attacks and on-death effects do not need API choices.
#   G_NOGEN describes random generation, not the turn taken by an existing NPC.
#
# How the list was checked
#   Matched the compiled terminal executable's --dumpenums against the active
#   MON definitions in include/monsters.h. Reviewed base speed, attack arrays,
#   flags, special movement, quest roles and action dispatch for all 383 IDs.
#   CHARON is off in this build (Charon and Cerberus). MAIL_STRUCTURES retains
#   the mail daemon ID even with NOMAIL. Disabled #if 0 definitions are outside
#   the compiled roster.
#
#   Tested 370 mobile, non-placeholder forms in an isolated wizard build with
#   every PM_* temporarily registered under its own wire name. Each trial
#   placed an awake actor in a lit room four squares from the hero, with water
#   for aquatic species. A local scripted broker chose an offered direction.
#   A move counted only when the exact form requested it, the engine replied
#   applied, and the actor's final displacement matched. This exercises a real
#   game turn. Coverage of spell effects, role scripts, campaign progression and
#   every terrain or inventory combination requires targeted encounters.
#
#   move           Movement observed in the first setup (341).
#   prepared-move  Movement observed on retry with native shape normalization,
#                  protection from shape changers, an awake actor and a
#                  petrification-resistant hero (12).
#   no-choice      No matching move in either setup (17).
#   source         Excluded from the movement trial by design (13).
#   The wizard-check column records the original audit. To verify the active
#   config, run test/decision-characters/roster.py against a --test build.
#   It checks an applied decision and two-turn history for every enabled form.
#   Passing --live exercises the real Decisions service once per form.
#   On 2026-11-19, all 281 enabled forms applied a live API choice in wizard
#   mode using a 5000 ms total budget. All 281 also passed the scripted
#   two-turn test with the default 500 ms budget on Linux.
#   A wizard-created shopkeeper or guard body can move without its role flag.
#   Those successes do not exercise a staffed shop or a live vault escort.
#
# What to preserve when extending a conditional row
#   A chosen action can return from dochug before mind blast, royal jelly,
#   inventory digestion, an undirected spell, quest speech or a taunt.
#   The native choice reaches these paths. Progression-critical effects must
#   also run when the model repeatedly chooses another action. Covetous actors
#   run tactics before the hook but can attack an artifact holder in m_move.
#   Applying runtime role fixes matters for the Master of Thieves in particular.
#   Temple priests, shopkeepers, minions and guards must retain their assigned
#   duties even when hostile. Endgame and role rows call for tests in context.
#
#   Native postmov handles metal and corpse eating after a normal step. For a
#   corpse already underfoot, m_search_items can also spend the turn feeding.
#   A generic wait skips that path. Other examples include a tengu teleport,
#   a unicorn's escape and a long worm's separate tail attack. Medusa's gaze
#   can kill before a choice and is skipped by the regular attack dispatcher.
#
# Evidence in this checkout
#   include/monsters.h and include/mondata.h -- roster, forms and trait macros
#   src/mon.c -- mcalcmove, movemon_singlemon, normal_shape
#   src/monmove.c -- dochug, m_move, m_search_items, resolve_step, postmov
#   src/decision.c and src/decision_actions.c -- eligibility, menu and execution
#   src/mhitu.c, src/muse.c and src/worm.c -- attacks, items and worm segments
#   src/makemon.c, src/shk.c, src/vault.c, src/priest.c -- assigned roles
#   src/role.c, src/quest.c and src/wizard.c -- quest roles and artifact pursuit
#   include/decision_prompts.conf -- configuration for the active subset
#
